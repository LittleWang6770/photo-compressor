# 照片轻装 · macOS 0.2.0

Swift 编写的本机照片批量压缩 App，macOS 13 或更新版本。当前已构建版本为 Apple Silicon 原生程序。

直接打开 `build/照片轻装.app`。首次可点击「用合成样张试试看」，整个体验仅处理临时目录中的生成素材。界面遵循 `mac-photo-app-ui`，沿用「焦段统计」的浅灰背景、白色步骤卡片与蓝灰主按钮；左侧设置，右侧照片对比，底部独立进度。

## 使用

1. 用系统 Finder 选择面板添加一个或多个来源文件夹，选择仅当前层或递归扫描。
2. 添加、移除来源或切换扫描范围后，自动统计待处理照片的数量与原始体积。统计期间实时更新已发现数量；扫描结果存入磁盘清单，界面只保留体积最大的一张候选路径。
3. 点击「生成最大照片样张」。在所有符合条件的照片中按文件字节数选最大的一张（同体积时按路径稳定排序）。滑动或输入 1–100 的质量分数后，对这张样张进行完整尺寸的实际编码，显示体积变化。四格同时对照原图、压缩图与对应的 100% 细节；上方点击定位、下方同步拖动，也支持方向键。
4. 默认选择「导出副本」，在来源之外选择输出文件夹，确认范围后开始压缩。也可选「原地覆盖原件（危险）」，按两步确认执行。保存格式与像素尺寸保持一致。

副本直接保存为 `所选输出位置/原文件名.JPG`，不再创建质量、来源或原子目录层级。例如选择 `compressed` 就得到 `compressed/IMG_0001.JPG`。多个来源或子目录有同名文件时，后续文件以 `原名-Q质量-来源摘要.JPG` 区分，不覆盖已有文件。断点续跑时选择相同来源、输出位置和质量，已经完成且标记匹配的副本会跳过。默认只写入体积变小的照片；关闭高级设置中的开关可写入变大的结果。

「查看记录」打开 JSON Lines 文件所在位置。扫描记录包含不支持、已标记和无法读取的项目；每次批处理单独记录成功、无收益、已完成和失败的路径、原因及体积。批处理记录位于 `~/Library/Application Support/照片轻装/处理记录`，不会额外占用副本目录。原地覆盖在每张照片提交前同步写入准备记录，成功后写入覆盖记录；记录不是原件备份。JSONL 用磁盘逐行写入，避免大列表常驻内存。

## 危险操作

两个危险选项每次启动默认关闭。

- 原地覆盖：选择后显示红色主按钮，先核对来源、数量、质量，再输入「覆盖原件」才可开始。每张照片先在来源目录生成临时文件，完整编码、校验并同步后，以原子交换替换原路径；成功后删除旧文件，不保留备份，App 无法撤销。停止只影响尚未提交的照片。执行结束、取消或失败后需要重新统计，避免使用旧清单与样张。
- 重复压缩：在「危险操作」中开启「允许重复压缩（第 2 次及以后）」，自动重新统计，已标记照片也会纳入；仍以所有待处理照片中体积最大的一张生成样张。可结合副本导出或原地覆盖。副本模式需输入「重复压缩」，原地模式需输入「覆盖原件」。标记记录最新质量、上次质量、累计次数与首次源体积，兼容旧版标记。提高质量分数无法恢复前次有损压缩丢失的细节。

旧版保存的来源授权为只读。首次原地覆盖时需点击「授权来源文件夹写入…」，在系统面板重新选择相同来源，授权完成才能开始。新添加的来源会保存读写书签。来源被外部修改、文件锁定/只读、有硬链接或不属于当前用户时不覆盖。文件系统不支持安全原子交换时记录失败并保留原件，不降级为直接截断写入。原地替换还会保留并校验文件身份，复制扩展属性（如 Finder 标签）、ACL 与权限。异常竞争导致无法回滚时保留旧文件并在记录中给出恢复路径。

## 支持范围与元数据

本版压缩单张、8-bit SDR 的 JPEG、HEIC/HEIF，保留像素尺寸和格式。质量分数控制编码器画质，不等于体积比例；100 不保证无损。预估百分比是当前一张样张的完整编码实测，不能保证整批比例，也不是内容质量评分。

- JPEG：将源文件的 APP0–APP15、COM 数据段移植到新编码的图像上，包括 EXIF、GPS、镜头机身信息、MakerNote、ICC、XMP 等。除 MPF 中必须更新的主图长度与预览位置索引外，其他数据保持逐字节一致；独立 APP15 写入 JSON 压缩标记，重复压缩时替换本应用的旧标记，不挪用用户备注或相机厂商字段。
- 相机 MPF 大预览：MPF 不一定表示 HDR 或多视角照片。支持「普通主图 + 大预览 JPEG」的组合，原样复制主图之后的全部预览、填充及尾部数据，仅重定位 MPF 指针并更新主图长度；回读验证索引和预览字节。对未知类型、增益图、全景、多视角以及损坏或越界索引继续安全跳过。
- HEIC：复制 Image I/O 可读取的元数据，在自定义 XMP 命名空间写入标记。回读并比较原 EXIF/GPS/TIFF/IPTC/ExifAux 字典和元数据标签；不一致则放弃副本并记录原因。系统可能规范化 HEIC 容器，因此不能承诺保留未知的私有容器结构。
- 输出文件复制并校验原创建与修改时间。允许约 2 秒误差以适配部分外置盘的时间精度。副本不修改原文件时间，原地覆盖保留原创建与修改时间（文件系统状态变更时间 ctime 会更新）。
- 标记包含应用 ID、版本、是否已压缩、最新质量、上次质量、累计次数、当前及首次源体积、来源状态摘要、压缩时间。来源状态摘要包含路径、大小、修改时间、文件设备/inode 与状态变更时间。被本应用标记的源照片默认自动跳过；复制文件时标记随图像保留。其他软件重新导出可能清除标记。来源摘要不是完整文件内容的密码学哈希。
- 发布前完整解码输出并校验尺寸、方向、元数据、标记和文件时间。临时文件位于目标目录；副本以 `renamex_np(RENAME_EXCL)` 原子发布，重名目标不会覆盖；原地以 `RENAME_SWAP` 交换，并在提交前后校验来源身份与状态。

RAW、PNG、TIFF、视频、应用包、隐藏文件和符号链接不处理。真正的多帧/HDR JPEG、高位深、特殊色彩模型、带深度/HDR/人像辅助图像的 HEIC，以及超过 1.5 亿像素的照片会安全跳过并记录原因。统计结束后来源区显示跳过/需检查数量，可直接查看原因。视频配对文件保留在来源中，本版不创建可重新导入相册的完整 Live Photo 配对包。原地覆盖仅处理上述支持且校验通过的照片。

## 性能与硬件

采用 Apple Image I/O 原生编解码，Swift/GCD 并行队列。自动并发最多 4 路，也可选 1/2/4/8 路；最终按本机内存与本批最大像素量进一步限流。每张任务独立释放临时对象，扫描任务清单流式读写。停止时等待当前系统编码返回，取消未发布的临时结果，保留已经完成的副本或覆盖结果。进度使用单调时钟与实测处理量平滑估时；扫描未知总量时显示「估算中」。

系统自行选择 Image I/O 的硬件路径。本版**没有显式 Metal GPU 或 Neural Engine 编码器，也未测量实际硬件占用率**，不能把系统编码等同于保证 GPU/NPU 加速。JPEG 编码常适合 CPU/SIMD；NPU 不是此处 JPEG/HEIC 的直接编码接口。后续可在同一元数据与校验框架下实测 libjpeg-turbo/Jpegli 后端，再决定是否替换。当前无第三方运行依赖。

已验证的是合成素材和中小批任务；尚未在真实 TB 级图库、网络卷或所有相机的私有元数据上做压力测试。TB 级吞吐还取决于磁盘、图像像素、格式、内存与校验开销。

## 构建与验证

需要 Apple Command Line Tools，无需 Xcode 工程或网络依赖：

```sh
zsh scripts/build.sh
zsh scripts/verify.sh
zsh scripts/verify-model.sh
zsh scripts/verify-danger.sh
```

构建脚本会生成本机架构的 `.app`、图标并做 ad-hoc 签名。没有 Developer ID 公证或 App Store 发布。自动验证使用本项目 `build/verification-*`、`build/model-verification-*`、`build/danger-verification-*` 的合成素材与临时目录；在 Codex 文件系统沙盒内，HEIC 编码和 `iconutil` 需要在沙盒外运行才能访问系统服务，普通终端不需要额外设置。
